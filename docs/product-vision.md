# 产品定位与范围

> 基线日期：2026-10-16。本文描述目标产品，不代表已实现能力。

## 1. 项目背景

项目发起者准备在微信公众号、小红书、今日头条等平台持续创作，可能同时运营多个不同类型的账号，希望 AI 能帮助处理创作中的重复劳动，同时保留自己的判断、表达和素材积累。

目前的痛点不是单独缺一个写作聊天框，而是整个工作过程分散：

1. 账号定位、受众和文风需要反复解释给 AI。
2. 灵感、参考文章、图片、写作草稿散落在多个地方。
3. 同一个主题需要转换成不同平台、不同账号的内容。
4. 排版、封面、配图和平台字段需要重复处理。
5. 不容易记住哪篇内容在哪个账号发过、哪个版本待发布。
6. 发布后的表现难以与原始选题、文风和素材联系起来。

## 2. 一句话定位

**一个可以自部署、理解不同账号创作风格、让内容资产持续积累的 AI 自媒体工作台。**

暂定名称为 One-Creator，正式命名、仓库名称及许可证见 [决策记录](decisions.md)。

## 3. 已知需求与规划假设

| 类别 | 当前认识 |
| --- | --- |
| 已明确需求 | 首先满足发起者自己的日常创作，同时希望开源 |
| 已明确需求 | 微信公众号、小红书、今日头条等多平台；每个平台可能有多个账号 |
| 已明确需求 | 不同账号具有不同内容定位，需要 AI 辅助 |
| 已明确需求 | 建立文档和长期功能进度记录 |
| 用户倾向 | 浏览器扩展不适合作为产品主体，倾向 Docker 部署 |
| 规划建议 | Web 工作台作为主要入口，核心操作不依赖安装扩展 |
| 规划建议 | 首阶段先打通图文创作，视频作为后续可选模块 |
| 尚待确认 | 实际账号类型、账号数量、内容领域、部署设备、技术栈偏好 |

## 4. 用户与使用场景

### 主要用户：独立创作者

一个人维护若干账号，需要在不同风格之间切换，希望把时间用于选题判断和内容打磨。

### 后续用户：小型内容团队

在同一工作空间共享素材与模板，分配账号权限，协作创作和排期。这是后续能力，首版使用流程应保持单人友好。

### 代表场景

以下账号定位均为设计示例，不代表用户已拥有这些账号。

| 场景 | 期望结果 | 关联需求 |
| --- | --- | --- |
| 同时运营科技公众号和生活类小红书账号 | 切换账号后，素材引用范围和写作偏好正确切换 | `ACC-01`～`ACC-03`、`MAT-04` |
| 一次研究分别写公众号、小红书、头条版本 | 共享事实素材，各版本独立编辑并保留来源关系 | `CRE-05`、`FMT-01`、`FMT-02` |
| 收藏链接后，周末集中写作 | 素材可搜索、可引用，失效链接仍保留已保存内容 | `MAT-01`～`MAT-05` |
| 文章写完但还没准备发布 | 保留待发布版本，安排日历，随时恢复编辑 | `CRE-04`、`PUB-03` |
| 自动发布通道不可用 | 仍能导出成品，在平台完成发布并回填链接 | `PUB-01`、`PUB-04` |
| 已发布内容表现不错 | 关联版本、指标和复盘，形成可编辑的后续写作建议 | `DAT-01`～`DAT-04`、`ACC-06` |

## 5. 核心产品对象

- **创作身份 / 人设**：创作者的定位、受众、表达风格和视觉偏好，可以用于多个平台账号。
- **平台账号**：某个平台中的实际账号；同平台可以存在多个账号。
- **账号连接**：该账号的一种 API 授权或浏览器登录会话。建立账号档案不要求先完成授权。
- **素材**：用户积累的文本、链接、图片、文件及引用信息。
- **内容项目**：围绕一个选题组织的母稿、素材和多个平台版本。
- **母稿**：事实和核心观点的来源版本，不等于最终发布文案。
- **平台版本**：面向一个目标账号形成的标题、正文、标签、封面和配图组合。
- **发布任务**：对一个确定版本执行存草稿、正式发布、定时提交或人工记录。
- **复盘**：将具体发布记录与指标、作者判断关联起来。

详细关系见 [数据模型](data-model.md)。

## 6. 完整工作链路

```text
账号定位与写作偏好
        ↓
灵感 / 热点 / 素材积累 → 选题与创作要求
        ↓
大纲 → 母稿 → 分账号、分平台版本
        ↓
排版 / 封面 / 配图 / 审校建议
        ↓
日历与发布任务 → 草稿推送 / 正式发布 / 导出与回填
        ↓
表现记录 → 复盘 → 更新选题和写作偏好
```

用户可以从任何一步进入，例如直接导入已写好的文章排版，或只使用账号管理和发布日历。

## 7. 产品设计原则

1. **按账号组织上下文**：创作时能看见目标账号及实际使用的偏好，不在不同账号间隐式混用。
2. **内容可持续编辑**：AI 生成的是可保存、可修改、可比较的内容资产。
3. **一份研究、多种表达**：适配平台时可以改变结构和篇幅，但引用事实与出处保持可追踪。
4. **能力如实显示**：生成文稿、上传素材、存入草稿、提交审核、正式发布分别记录。
5. **部署负担渐进增加**：基础创作可独立使用，浏览器执行器、向量检索、视频服务按需启用。
6. **开放且可迁移**：核心内容可导出；模型、存储、发布通道通过清晰接口替换。
7. **全景规划、分阶段兑现**：功能目录完整保留，每个阶段必须交付实际可用的创作链路。

| 领域 | 目标能力 | 需求前缀 |
| --- | --- | --- |
| 系统 | 部署、登录、模型、任务、备份、用量、通知、协作 | `SYS` |
| 账号 | 账号矩阵、人设、偏好、授权、风格提炼、长期记忆 | `ACC` |
| 选题 | 灵感池、热点订阅、选题推荐、对标观察、系列内容 | `IDEA` |
| 素材 | 导入、媒体库、检索、引用、网页提取、语义检索 | `MAT` |
| 创作 | 创作要求、分步生成、编辑、版本、一稿多改、模板、工作流 | `CRE` |
| 视觉 | 公众号排版、小红书卡片、封面、AI 配图、主题模板 | `FMT` |
| 审校 | 平台字段检查、语言建议、事实引用检查、版本评估 | `REV` |
| 发布 | 导出、草稿、日历、适配器、自动发布、调度和执行节点 | `PUB` |
| 复盘 | 指标导入、数据同步、看板、效果复盘 | `DAT` |
| 开放 | REST API、Webhook、MCP | `EXT` |
| 视频 | 转写与脚本、短视频合成、长视频切片 | `VID` |
| 运营扩展 | 评论处理、合作与收益记录 | `OPS` |

## 9. 首个可用版本建议

从一条完整任务验证价值：**建立两个不同风格的账号 → 导入自己的素材 → AI 辅助写作 → 生成三类平台版本 → 排版与导出 → 记录发布结果**。

首阶段同时建立 Docker 部署、登录、持久化、任务记录和备份能力。公众号草稿通道按实际权限验证后接入，不能以“理论有 API”代替验证。

热点自动发现、样文风格提炼、自动发布、语义检索、团队协作和视频逐步加入。详细范围见 [开发路线图](roadmap.md)，每项的目标阶段见 [开发进度](progress.md)。

## 10. 如何判断产品有用

以发起者真实使用记录建立基线，再设定数值目标：

- 完成一篇多平台内容需要多长时间，重复复制与排版用了多久？
- AI 输出中最终采用了多少，哪些部分仍需重写？
- 是否能准确找回某个账号、某次发布的最终稿和素材？
- 不同账号的内容风格是否符合作者预期？
- 发布任务能否给出明确结果，异常能否接着处理？
- 恢复备份后是否还能继续使用已有内容？

浏览量、涨粉量用于后续复盘，不作为首版软件功能是否完成的判定标准。
