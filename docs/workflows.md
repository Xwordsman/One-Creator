# 用户流程、页面结构与状态约定

> 日期：2026-10-16。以下为交互与业务规则草案；详细功能定义见 [需求文档](requirements.md)。

## 1. 主要页面

| 页面 | 用户要完成的事 | 主要对象 / 需求 |
| --- | --- | --- |
| 工作台首页 | 查看继续创作、近期排期、待处理任务 | 内容、任务；`SYS-04`、`PUB-03` |
| 账号与人设 | 建档、管理不同定位、配置连接 | 账号、人设、连接；`ACC-*` |
| 选题中心 | 记录灵感、采用推荐、规划系列 | 选题、订阅；`IDEA-*` |
| 素材库 | 保存文章与图片、查找资料、追溯引用 | 素材、文件；`MAT-*` |
| 内容库 | 按账号、平台、栏目查找内容项目 | 母稿与版本；`CRE-04`、`CRE-05` |
| 创作编辑页 | 填创作要求、分步生成、编辑、比较版本 | 创作会话、文稿、引用；`CRE-*` |
| 排版与图片 | 微信排版、卡片、封面与配图 | 版式、资源；`FMT-*` |
| 发布中心 / 日历 | 选择版本和账号，导出、存草稿、排期，查看结果 | 发布任务；`PUB-*` |
| 数据与复盘 | 录入指标、分析内容、记录经验 | 快照、复盘；`DAT-*` |
| 设置 | 模型、存储、备份、通知、访问令牌 | 系统配置；`SYS-*`、`EXT-*` |

未实现的模块不应通过静态样例伪装成可用功能。首阶段菜单应聚焦已交付能力。

## 2. 首次使用

```text
Docker 启动 → 初始化用户 → 进入个人工作空间
          → 配置文本模型并测试
          → 建立账号档案与人设
          → 创建第一条选题或直接导入文章
```

- 模型未配置时仍可以手工编辑、保存素材。
- 账号未授权时仍可以绑定写作风格、生成内容和导出。
- 用户能够清楚区分工作台登录账号与公众号 / 小红书等平台账号。

## 3. 流程 A：从选题创作一篇内容

1. 手工记录想法，或从热点条目采用选题。
2. 选择创作身份、目标账号，填写内容目的和期望形式。
3. 从素材库选择资料，补充自己的观点与经验。
4. 生成大纲，用户编辑后继续写正文；也可跳过 AI 手工写作。
5. 局部修改、选择标题，保存一个明确的内容版本。
6. 保留创作要求、人设版本、引用材料和模型执行记录。

关键异常：AI 失败保留已有内容；换账号不静默重写已保存稿件；资料不足时提示缺项。

## 4. 流程 B：一稿多平台、多账号

1. 从确定的母稿版本派生目标版本。
2. 每个派生版本选择一个目标账号，并使用该账号偏好。
3. 公众号版本进行长文排版；小红书版本生成图文结构和卡片；头条版本调整结构与字段。
4. 用户可以独立修改三个版本。
5. 母稿再次更新时，旧派生版本提示“来源版本已更新”，由用户选择重生成或继续使用。

同平台两个账号也需要两份独立派生版本。即使正文暂时相同，也不能只用平台名代替目标账号。

## 5. 流程 C：排版与发布准备

1. 选择目标版本、封面和媒体顺序。
2. 预览平台呈现，处理确实存在的字段或媒体限制。
3. 创建发布任务时冻结版本、媒体、账号和通道。
4. 选择当前可用动作：导出、存平台草稿、立即提交或排期。
5. 任务提交后仍可编辑内容，但新编辑属于另一版本，不改变已创建任务的快照。

审校建议和平台必填错误应有不同表现；改写建议不能无提示地修改作者文稿。

## 6. 流程 D：自动通道与人工发布

### 官方草稿通道

```text
选定快照 → 校验账号连接和能力 → 上传媒体 → 写入草稿
        → 返回平台草稿 ID → 在任务中查看草稿结果
```

“已保存平台草稿”是这一任务的完成状态，不显示为“已发布”。正式发布是另一个有权限要求的动作。

### 浏览器通道

```text
选择账号 → 创建登录会话 → 显示二维码 / 待交互信息
        → 完成登录 → 校验实际身份 → 保存隔离会话
        → 领取发布任务 → 填写与提交 → 查询 / 核验结果
```

用户刷新页面不应导致第二份并行登录。验证码或人工交互通过同一会话继续；运行中的账号会话只由一个执行者写入。

### 导出与手工回填

```text
导出正文和图片 → 用户在平台发布 → 回填平台链接与时间
             → 工作台记录“用户回填”，关联发布快照
```

链接暂缺时可以保存备注，但必须显示记录来源及核验程度。自动状态查询不能伪装成手工记录的证据。

## 7. 流程 E：数据与复盘

1. 选择实际发布记录，录入或同步某个时间点的数据。
2. 展示指标来源与统计口径，保持原始值。
3. 作者补充“为什么这样写”“哪里需要改进”等笔记。
4. AI 可以提出选题、结构、表达建议，并引用依据。
5. 作者选择将建议加入特定账号偏好，形成新版本。

## 8. 状态应按对象分别记录

### 8.1 选题

| 状态 | 含义 |
| --- | --- |
| `inbox` | 收集到但尚未决定 |
| `selected` | 已采用，可以创建内容项目 |
| `parked` | 暂时搁置 |
| `archived` | 归档，保留来源和历史关联 |

### 8.2 文稿和平台版本

| 状态 / 标记 | 含义 |
| --- | --- |
| `editing` | 正在编辑 |
| `ready` | 作者认为该版本可用于发布准备 |
| `archived` | 不再主动使用，但保留历史 |
| `source_outdated` | 派生来源不是母稿最新版本，是计算标记而非发布状态 |

内容项目本身不设置一个能覆盖全部账号的单一“已发布”字段。首页的“部分已发”等汇总应从各发布记录计算。

### 8.3 账号连接

| 状态 | 含义 |
| --- | --- |
| `unconfigured` | 尚未配置连接 |
| `connecting` | 授权或登录进行中 |
| `ready` | 最近检查时连接可用，不代表具备所有操作权限 |
| `needs_login` | 会话已过期或需要重新授权 |
| `needs_interaction` | 等待用户完成扫码后步骤等交互 |
| `unavailable` | 通道当前不可用，附原因及最后检查时间 |
| `disabled` | 用户停用连接 |

连接状态与 `save_draft`、`publish`、`fetch_metrics` 等能力分开存储。

### 8.4 发布任务

| 状态 | 进入条件 | 后续处理 |
| --- | --- | --- |
| `planned` | 已保存快照和计划时间，尚未入执行队列 | 到时入队、调整排期或取消 |
| `queued` | 可以执行，等待执行者 | 取得任务与账号锁后运行 |
| `running` | 执行中，附当前阶段 | 保存阶段结果，进入相应结果状态 |
| `waiting_user` | 需用户处理连接、人工发布或过期排期 | 处理后继续、回填结果或取消尚未提交的任务 |
| `draft_saved` | 平台确认草稿保存并有草稿标识 | 草稿任务完成；正式发布另建任务 |
| `platform_scheduled` | 平台已接收原生定时安排 | 查询平台结果；不能同时由本地再提交一次 |
| `submitted` | 平台确认接收，最终审核或可见状态尚未确认 | 定期查询或由用户核实 |
| `published` | 平台确认已发布，或用户明确回填并标注来源 | 关联平台标识、链接、时间和证据 |
| `verification_required` | 可能已写入平台但回执丢失或结果矛盾 | 先查询 / 核验；不自动重发 |
| `failed` | 已知失败，记录失败阶段及是否有外部写入 | 符合重试条件时创建新的尝试 |
| `cancelled` | 已确认尚未发生目标提交且取消成功 | 保留记录，不再执行 |

关键转移约定：

- 存草稿：`queued → running → draft_saved`。
- 即时发布：`queued → running → submitted → published`；平台直接确认时可从 `running` 到 `published`。
- 平台原生定时：`running → platform_scheduled → submitted / published`。
- 任何可能发生写入但回执未知的步骤：进入 `verification_required`，不能直接当作可自动重试的失败。
- 人工发布：`waiting_user → published`，证据来源必须是 `user_recorded`。
- `verification_required` 可以经核实转为 `draft_saved`、`platform_scheduled`、`submitted`、`published` 或已知失败。
- 发布后编辑不改变历史任务。删除平台内容、撤回平台原生定时属于单独能力，不用本地“取消”按钮代替。

## 9. 调度与重试约定

1. 计划时间保存 UTC 时间点与 IANA 时区，界面默认可使用 `Asia/Shanghai`。
2. 每项计划只选一种调度执行方：本地队列、平台原生定时或人工提醒。
3. 服务器离线导致错过时间时，默认进入待处理，不在恢复后无提示地集中补发；后续可配置明确的宽限策略。
4. 以账号为互斥粒度，任务锁需有租约、续期及失联恢复规则。
5. 同一逻辑任务重复入队不等于新的发布意图。用户确实要再次发布时应建立新的任务。
6. 单个平台失败只影响该任务，不回滚其他平台已成功的发布。
7. 运行任务取消先表达取消请求；尚不能确定外部效果时保留待核验状态。

## 10. 关键异常如何表现

| 情况 | 预期用户体验 |
| --- | --- |
| 模型响应中断 | 保留已保存内容，可查看失败并重新生成指定步骤 |
| 登录过期 | 指明受影响的账号连接，其他账号继续可用 |
| 实际登录账号不符 | 展示期待账号与实际账号，不把稿件交给错误账号 |
| 图片上传部分失败 | 展示成功和失败的图片，重试时复用可用映射 |
| 平台提交超时 | 显示待核验，附可用回执和查询入口 |
| 双标签页修改冲突 | 保留两个修改，提示比较或另存版本 |
| 数据同步不可用 | 展示最后成功同步时间，并允许手工补充 |

上述流程的验收样例见 [验证计划](validation.md)。
