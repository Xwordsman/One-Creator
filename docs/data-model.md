# 数据模型与核心约束草案

> 更新：2026-10-18。本文是全量业务模型。当前已实现的结构以 `packages/server/src/migrations.ts` 为准（迁移 001～006）。
> 001～003：用户、空间、会话、账号、公众号连接、人设修订、灵感、素材、资源、摘录、文稿修订、模型、后台任务、操作记录与发布计划、上传检查点与草稿回执。
> 004～006：成员角色与账号授权、访问令牌、创作资源（`creator_items` 按 `kind` 区分）及修订、用量与价格快照、通知与事件、Webhook 订阅与投递、自动化任务与采用记录、订阅与条目、向量片段（`material_chunks`）、指标快照、正式发布字段、执行节点、浏览器连接、节点指令、账号执行租约。
> 与本文的差异：PublishAttempt / PlatformReceipt 以任务记录（`jobs`、`automation_jobs` 的尝试与进度）和发布计划上的平台 ID 字段实现，没有单独建表；浏览器会话本身不入库，只存在执行节点的加密文件中。

## 1. 核心关系

```text
User ── Membership ── Workspace
                         │
                         ├── Persona ── PersonaRevision
                         │       └── PlatformAccount ── AccountConnection
                         │                                  └── CapabilitySnapshot
                         ├── Idea ── ContentProject
                         │              ├── ContentRevision（母稿修订）
                         │              └── ContentVariant（一个目标账号）
                         │                       └── VariantRevision
                         ├── Material / Asset ── Citation（版本引用）
                         ├── AIRun / Job / JobEvent
                         └── PublishSnapshot ── PublishTask ── PublishAttempt
                                                     └── PublishRecord
                                                            ├── MetricSnapshot
                                                            └── Retrospective
```

首版只有一个个人工作空间也保留归属字段，后续成员权限扩展不需要重定义所有内容归属。

## 2. 账号与人设

| 对象 | 关键字段建议 | 约束 |
| --- | --- | --- |
| User | ID、登录标识、密码散列、状态 | 不与媒体平台账号混用 |
| Workspace | ID、名称、默认时区、默认偏好 | 首版可只建立个人空间 |
| Membership | 用户、空间、角色 | 首版可仅有 owner；多人功能再扩展 |
| Persona | ID、空间、名称、当前修订 ID | 创作身份可以跨平台共享 |
| PersonaRevision | 人设 ID、版本、定位、受众、文风、视觉偏好、样文引用 | 内容不可变；修改人设产生新修订 |
| PlatformAccount | ID、空间、平台键、平台用户 ID、显示名、主页、人设 ID、账号偏好、状态 | 昵称可变化；身份以平台稳定标识为准；未授权时允许平台 ID 为空 |
| AccountConnection | ID、账号、连接方式、凭据引用、会话资源引用、状态、检查时间 | 一个账号可有 API 与浏览器等多个连接；任何连接不得绑定其他账号会话 |
| CapabilitySnapshot | 连接、内容类型、操作、支持状态、原因、规则版本、核验时间 | `ready` 连接不等于所有操作可用；未知保留 `unknown` |

同空间内，已知的“平台键 + 平台稳定用户 ID”应避免重复建档。只填写相同昵称不应被误判为同一账号。

## 3. 选题与素材

| 对象 | 关键字段建议 | 约束 |
| --- | --- | --- |
| Idea | ID、空间、主题、想法、目标账号集合、来源、状态、计划日期 | 可创建多个内容项目，采用不删除原始想法 |
| Material | ID、空间、标题、正文、原始 URL、作者、来源时间、获取时间、分类、可见范围 | 原 URL 失效时仍能保留用户已保存的资料 |
| MaterialRevision | 素材、修订、已保存正文或摘录 | 被引用的内容不能因为重新抓取而静默替换 |
| Asset | ID、空间、存储键、文件散列、类型、大小、尺寸、来源、父资源 ID | 原始资源与派生产物分开；私有资源不依靠猜测 URL 隔离 |
| Citation | 内容修订、素材修订、引用片段、位置、来源状态 | 引用应指向具体修订，不只指向可能变化的 URL |
| Tag / Collection | 标签、集合、关联对象 | 按空间约束；关联不能跨越权限范围 |
| EmbeddingChunk | 素材修订、片段、模型、维度、索引版本 | 已实现（`material_chunks`，按模型指纹区分）；更换模型须重建，重建完成后清理该素材的旧片段 |

图片可能既是原始素材，也被多个内容版本引用。删除资源前应检查引用，不能直接造成历史发布快照缺图。

## 4. 内容项目与平台版本

| 对象 | 关键字段建议 | 约束 |
| --- | --- | --- |
| ContentProject | ID、空间、选题 ID、工作标题、栏目、状态、当前母稿修订 | 是内容集合，不用单一发布标记代表所有渠道 |
| ContentRevision | 项目、修订号、正文、结构化元数据、创作要求、人设修订、来源运行 ID | 母稿的不可变历史；正文编码格式待编辑器 POC 确认 |
| ContentVariant | 项目、目标账号、内容类型、状态、当前修订 | 同平台不同账号属于不同版本集合；同账号可有多个候选 |
| VariantRevision | 派生版本、修订号、来源母稿修订、标题、正文、摘要、标签、媒体顺序、封面、模板版本 | 保存完整可还原的内容；修改产生新修订 |
| RenderArtifact | 版本修订、渲染器版本、模板版本、参数、资源清单、结果散列 | 可追溯生成该 HTML / 卡片的输入 |

母稿更新后，若 `VariantRevision.source_revision_id` 不再等于项目当前母稿修订，显示来源过期标记。旧派生版本仍然有效，不能自动覆盖。

编辑保存使用预期修订号或等效的乐观锁；同一修订同时被两个标签页修改时返回冲突，不直接覆盖。

## 5. AI 与通用任务

| 对象 | 关键字段建议 | 约束 |
| --- | --- | --- |
| ModelProvider | ID、空间、类型、地址、凭据引用、能力配置 | 文本、图片和向量可分别配置 |
| AIRun | ID、任务、模型、模板版本、输入版本、上下文快照、输出版本、用量、费用来源 | 同一任务重试形成不同调用记录；记录实际模型，不假设预设就是最终调用 |
| Job | ID、空间、类型、状态、目标对象、幂等键、租约、当前尝试、计划时间 | 队列传递 ID，数据库保存权威状态 |
| JobEvent | 任务、事件 ID、序号、时间、阶段、脱敏详情 | 支持重连读取；同一事件重复消费不重复追加业务结果 |
| OutboxEvent | 事件 ID、对象、类型、载荷版本、投递状态 | 采用外部队列时保证业务写入与待投递事件的一致性 |

`Job` 描述一次执行活动，`PublishTask` 描述完整发布业务过程。一个发布任务可以先后产生上传、提交、状态查询等执行 Job；某个 Job 执行成功，不代表发布任务已经正式发布。执行状态与业务状态分别维护，并在同一事务边界内更新相关关联。

用量缺失与零用量有不同含义；费用保存币种、单价来源、估算 / 实际标记和计算时点。

## 6. 发布领域

### 6.1 发布快照

`PublishSnapshot` 至少包括：

- 工作空间、目标平台、目标账号及选定连接。
- 操作：`export`、`save_draft` 或 `publish`。
- 目标平台内容类型，例如公众号文章、小红书图文、头条文章。
- 选定的 `VariantRevision`、标题、正文、平台字段。
- 封面、图片顺序及已生成产物的资源 ID / 散列。
- 人设与平台规则版本、渲染器版本、创建者和创建时间。

发布任务执行时只读取该快照，不读取“当前编辑中的最新正文”。

### 6.2 发布记录对象

| 对象 | 关键字段建议 | 约束 |
| --- | --- | --- |
| PublishTask | ID、快照、动作、状态、执行连接、节点、调度模式、计划时间、时区、幂等键 | 调度模式只有一个执行方；调整已冻结内容应创建新快照并记录变化 |
| PublishAttempt | 发布任务、执行 Job、尝试号、阶段、开始结束时间、租约版本、错误、是否可能写入平台 | 外部状态不明确时不能直接启动新提交 |
| PlatformReceipt | 尝试、平台草稿 / 提交 / 帖子 ID、原始状态、规范状态、查询时间、脱敏回执 | 每个阶段收到标识后及时保存；平台名称相同不代表 ID 全局唯一 |
| PublishRecord | 任务、账号、平台帖子 ID、链接、实际时间、结果来源、证据引用 | 区分 `platform_confirmed` 和 `user_recorded`；可以尚无最终公开链接 |
| AssetUploadMapping | 账号、连接、资源散列、平台素材 ID / URL、有效期 | 账号范围内复用，不跨账号盲用素材 ID |
| ExecutorNode | ID、空间、授权账号范围、能力、版本、心跳、令牌摘要、状态 | 已实现（`execution_nodes`）；节点只能领取已授权任务，同一令牌只允许一个在线实例 |

### 6.3 幂等与内容指纹是两个概念

- **幂等键**识别同一次逻辑操作，重复点击、消息重投和网络重试使用同一个键。
- **内容指纹**识别同账号、同动作、同内容快照的相似或重复发布，用于提示和核对。
- 作者确实要再次发布时产生新的发布意图；不能用内容指纹永久禁止合理的再次发布。
- 若平台没有幂等接口，外部成功但本地未收到回执仍可能发生；此时进入待核验，而不是宣称系统实现绝对仅一次。

## 7. 指标与复盘

| 对象 | 关键字段建议 | 约束 |
| --- | --- | --- |
| MetricSnapshot | 发布记录、账号、指标键、数值、单位、口径、采样时间、来源 | 保留每个采样时点；累计值不能简单累加；缺失值为空 |
| Retrospective | 内容 / 发布记录、作者笔记、指标快照引用、模型建议、创建时间 | 能还原结论基于哪些数据 |
| PreferenceProposal | 目标账号 / 人设、建议内容、来源复盘、采用状态 | 采用后形成偏好新版本，不静默改旧版本 |

跨平台看板优先按平台分组展示。展示统一指标前先记录定义，例如“阅读次数”“播放次数”“曝光次数”不是同一口径。

## 8. 必须成立的数据约束

1. 工作空间内的关联对象归属一致；外键和服务端逻辑共同防止跨空间引用。
2. 账号与连接的对应关系可检查；任务的目标账号必须等于连接所属账号。
3. 母稿、平台版本、人设和渲染结果保留实际使用的修订。
4. 平台回执与任务动作相符：草稿 ID 不能被当成帖子 ID。
5. 单个逻辑任务只有一个有效执行租约；状态更新检测过期执行者。
6. 已发布结果不能因重试回调而回退为 `running`；事件处理需校验合法状态转移。
7. 时间点统一保存 UTC，用户的显示时区单独保存。
8. 删除账号优先使用停用 / 归档，保留历史内容和发布关系；彻底删除时有明确的数据清理范围。
9. 索引至少覆盖工作空间筛选、账号平台标识、内容修订、任务状态和到期时间、幂等键及平台回执定位。
10. 备份包含数据库与引用文件的可对应版本，恢复时能够验证缺失资源。

## 9. 分阶段落地

- v0.1：用户 / 空间、账号 / 人设、基础素材、母稿 / 派生修订、任务、导出与草稿记录、凭据引用。
- v0.2：订阅、embedding、定时与浏览器通道的扩展字段、用量、公共令牌和事件投递、手工指标。
- v0.3 及以后：成员权限、独立执行节点、自动指标同步、复盘学习、视频和运营台账。

概念对象不必一一对应独立表；实现前可合并简单对象，但不能丢失版本、归属和状态语义。
