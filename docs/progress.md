## 2. 状态与优先级

| 状态 | 使用条件 |
| --- | --- |
| `TODO` | 已记录，尚未开始实现 |
| `DOING` | 正在实现；部分完成也使用此状态并记录剩余项 |
| `VERIFY` | 已有可检查的实现，等待对应验收 |
| `DONE` | 实现与验收均满足，有日期和证据 |
| `BLOCKED` | 已进入工作，但因具体依赖无法继续；必须记录原因和解除条件 |
| `DEFERRED` | 明确延后；保留需求与调整原因 |
| `DROPPED` | 已决定取消；保留历史和决策引用 |

- **P0**：基础使用链路与必要质量能力。
- **P1**：重要效率提升或需要外部条件的能力。
- **P2**：扩展能力，按实际使用再排顺序。

优先级不等于目标版本，也不代表用户已逐项确认范围。

## 7. DONE 的判定

标记完成时必须满足：

1. 对应需求的用户结果确实可用，验收条款均有检查结果。
2. 正常路径和与该需求直接相关的异常路径已验证。
3. 写明实现位置和验证方式；外部平台能力写明实测范围。
4. 记录完成日期、剩余限制和关联决策。
5. 更新本表、必要的使用说明和变更记录。

仅有 UI、模拟接口、外部项目文档或生成的测试代码，不足以单独证明完整功能完成。
