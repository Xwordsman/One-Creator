# 技术架构草案

> 更新：2026-10-18。本文保留整体目标架构；当前实现的实际选型与边界见下节。
> 开发入口见 [开发指南](development.md)，部署入口见 [部署说明](deployment.md)。

## 0. 当前已落地的架构

- React / Vite Web + Fastify API，TypeScript 共享类型与 Zod 输入校验。
- PostgreSQL 生产配置、PGlite 本地开发配置，使用同一建库迁移。
- 数据库中的 AI / 公众号任务表，事务领取、租约与阶段、结果保存、取消与人工重试；开发内联，生产独立 worker。浏览器导入、卡片、裁剪和服务端导出记录通过统一任务列表展示。
- Markdown 母稿、派生版本、修订、素材与摘录快照；公众号官方草稿与正式发布适配器已接入。
- 平台写入前保存精确请求与上传检查点；中断后进入待核对，认领完全匹配的草稿 / 文章或经人工确认后才可重试；迟到执行者受租约约束；同一账号的平台写入由账号执行租约串行。
- 通用自动化任务表（`automation_jobs`）承载 AI 辅助、订阅、导入、索引、配图、转写、视频、发布与核对；结果先作为候选，采用另行记录。调度器从数据库派发到期计划。
- 浏览器发布由独立执行节点完成（`apps/executor`，Playwright + Chromium），节点经 HTTP 领取任务，平台会话只在节点本地加密保存。视频由可选 FFmpeg 媒体服务（`apps/media-service`）处理。
- 语义检索的向量保存在数据库 JSON 字段，按需在进程内计算相似度；未使用 pgvector，适合个人规模。
- 文件卷存图片与媒体，模型 Key、公众号 AppSecret、令牌、Webhook 密钥与节点指令使用 AES-GCM 加密；平台凭据加密范围绑定具体账号。成员按角色与账号授权访问，所有业务查询按工作空间与授权范围过滤。
- 开放接口：`/api/v1` REST、OpenAPI 文档、Bearer 访问令牌、HMAC 签名 Webhook、MCP（JSON-RPC）。
- npm workspaces；MIT 项目许可。没有引入 Redis。

本地运行已经进入功能验证；Compose 文件已提供，当前开发环境没有 Docker，不能将容器部署视为已经实测通过。

## 1. 架构目标

1. Web 工作台集中管理账号、内容和任务，优先支持 Docker 自部署。
2. 个人基础部署尽量简单，逐步增加浏览器、向量检索和视频能力。
3. 内容管理不依赖某个发布通道；发布失败不影响继续写作和导出。
4. 生成和发布使用持久化任务，页面关闭后仍可查看结果。
5. 多账号的内容上下文、连接、媒体映射和任务互相隔离。
6. 已使用的内容版本、模型参数和平台结果可追踪。

## 2. 推荐结构：模块化业务服务 + 独立任务进程

```text
浏览器 Web 工作台
        │ HTTPS / JSON / 任务事件
        ▼
应用服务（Web 资源 + 业务 API）
├── 登录 / 工作空间 / 账号 / 人设
├── 选题 / 素材 / 内容与版本
├── 模型配置 / 创作编排
├── 发布能力 / 日历 / 结果记录
└── 后续：数据复盘 / REST API / Webhook / MCP
        │
        ├── 关系数据库：业务数据、任务状态、事件
        ├── 文件存储：素材、排版产物、发布快照
        └── 队列边界：数据库任务表或专用队列（待选）
                      │
                      ▼
                通用 worker
                ├── 文本生成 / 导入 / 渲染
                ├── 官方 API 草稿与发布
                └── 调用可选执行服务
                      ├── browser worker：隔离浏览器会话
                      ├── 视频 / ASR 服务
                      └── 后续独立执行节点

外部依赖：用户配置的模型服务、平台 API、热点源、可选组件
```

应用服务和通用 worker 可以来自同一代码库、同一镜像，以不同进程运行。模块划分首先是代码和职责边界，不要求首版拆成多个微服务。

## 3. 部署组合建议

| 组合 | 组成 | 适用阶段 |
| --- | --- | --- |
| 基础图文 | 应用服务、worker、关系数据库、持久化文件卷 | 首个可用版本 |
| 队列增强 | 在选定 Redis 等方案时增加对应服务 | 按任务实现选择，不默认堆叠组件 |
| 浏览器发布 | 增加 browser worker、会话卷和必要字体 / 浏览器运行依赖 | 小红书、头条通道验证后 |
| 语义检索 | 启用向量索引和单独配置的 embedding 服务 | 素材语义检索阶段 |
| 对象存储 | 将本地文件存储替换为 S3 兼容存储 | 多节点或素材量增加时 |
| 视频扩展 | 增加媒体服务，必要时配置 GPU 或外部生成 API | 视频阶段 |

当前 Compose 位于 `deploy/compose.yaml`，默认包含 app、worker、postgres；`--profile media` 增加 FFmpeg 媒体服务，`--profile executor` 增加浏览器执行节点（也可在作者自己的电脑上运行）。

## 4. 前序选型候选与后续扩展依据

此表保留初始比较方向；当前选择以第 0 节和 `decisions.md` 为准。

| 层 | 建议评估方向 | 理由与待验证点 |
| --- | --- | --- |
| 前端 | React / Next.js 或 Vue 3 / Vite | 两者都可做工作台；由维护者熟悉程度、编辑器和渲染组件决定 |
| 业务后端 | TypeScript / NestJS 优先候选；也可按维护经验选 Python 等 | TypeScript 与排版组件、前端类型共享方便；不因候选组件语言锁死整个系统 |
| 数据库 | PostgreSQL 优先候选 | 关系、JSON、事务、后续 pgvector 可集中处理；首版向量扩展可不启用 |
| 任务 | 数据库持久化任务，或 Redis 支撑的成熟队列 | 先验证恢复、重试、取消和定时；不把 Postiz 使用 Temporal 当作本项目必须使用的理由 |
| 文件 | 本地持久化卷 + 存储接口；后续 S3 兼容 | 降低单人部署成本；原始文件与数据库均可备份 |
| 编辑与正文 | Markdown + 结构化元数据的初始方案 | 易导入导出；富文本编辑器、往返格式损失需要 POC |
| 微信排版 | 文颜核心库 / doocs/md 渲染能力候选 | 验证服务端渲染、主题和编辑器粘贴效果后选择 |
| 卡片 | HTML / Canvas 模板化渲染 | 保持文字可编辑与分页可控；前后端渲染结果需一致性验证 |
| AI 接入 | provider 接口，按能力调用模型 | 聊天兼容不代表图片、向量或工具调用也兼容 |
| 浏览器执行 | Playwright 类 worker；也可接独立 MCP 服务 | 具体工具由通道验证决定，会话生命周期由本系统管理 |
| 媒体处理 | 独立 Python / FFmpeg / 第三方任务 API | 独立资源预算和产物接口，基础部署不依赖重型媒体栈 |

## 5. 模块边界

| 模块 | 拥有的数据和职责 | 不应承担的职责 |
| --- | --- | --- |
| Workspace / Access | 用户、工作空间、权限 | 直接执行平台发文 |
| Accounts | 账号档案、人设、连接、能力快照 | 把一个连接的状态当作整个平台状态 |
| Materials | 原始资料、资源文件、引用片段、检索 | 把网页内容当成系统操作指令 |
| Content | 创作要求、母稿、派生版本、修订历史 | 将某次生成结果直接覆盖最新人工稿 |
| AI | 模型选择、上下文构建、生成记录、用量 | 自行选择未绑定的目标账号发布 |
| Rendering | 平台排版、卡片、媒体规格转换 | 修改原始母稿或凭据 |
| Publishing | 快照、排期、平台适配、执行记录、结果核验 | 用 HTTP 成功响应推断平台正式发布成功 |
| Analytics | 指标快照、口径、复盘 | 把缺失数据填成零或把累计值重复相加 |
| Integrations | REST / Webhook / MCP 边界 | 绕过核心权限和任务规则 |

## 6. 内容与 AI 上下文

### 6.1 每次生成保存上下文快照

- 工作空间、创作身份、人设版本、目标账号。
- 本次创作要求和已选择素材 / 引用。
- 实际模板版本、参数、平台规则版本。
- 模型服务、模型名称、请求 ID、用量与结果。
- 输入和输出对应的内容版本。

平台硬性技术约束单独校验。写作偏好建议按以下优先级合并：

```text
本次任务的明确要求
    > 账号专属偏好
    > 共享创作身份偏好
    > 平台风格模板
    > 工作空间默认偏好
```

资料和样文作为参考输入，不覆盖业务权限或账号选择。凭据不进入模型上下文。

### 6.2 分步执行

`创作要求 → 大纲 → 正文 → 平台适配 → 排版 / 配图`分别保存产物。首版可以是固定编排，不需要先建设通用多 Agent 平台。

生成结果附带预期编辑版本；如果用户已经继续修改，结果保存为候选修订，交给用户比较采用。

### 6.3 模型能力

按 `text`、`image`、`embedding`、`speech`、`video` 等能力配置，记录服务支持的参数。连接测试应验证选定能力，而不仅是服务地址能响应。

备用模型仅在用户已配置的方案内使用，并记录实际调用及额外费用。基础编辑不依赖模型在线。

## 7. 发布适配器契约草案

平台适配器为业务层暴露标准操作；没有对应能力时返回明确的 `unsupported`，不是虚构成功。

| 操作 | 输入 / 输出约定 |
| --- | --- |
| `getCapabilities` | 账号连接 → 能力、限制、理由、核验时间、规则版本 |
| `beginLogin` / `getLoginStatus` | 会话标识 → 二维码、状态、过期时间或交互说明 |
| `checkIdentity` | 账号连接 → 实际平台身份，与预期账号比对 |
| `validate` | 冻结的发布快照 → 平台字段错误与建议 |
| `uploadMedia` | 账号连接 + 资源 → 账号范围内的平台素材映射 |
| `saveDraft` | 快照 + 幂等上下文 → 草稿 ID、链接或待核验结果 |
| `publish` | 快照 / 草稿 ID → 提交 ID、初始状态、证据 |
| `getPublishStatus` | 提交 ID / 草稿 ID / 其他可用定位信息 → 真实状态与时间 |
| `fetchMetrics` | 发布记录 → 指标值、口径、采样时间 |
| `export` | 快照 → 文稿、媒体和清单文件 |

能力值至少区分 `supported`、`unsupported`、`unknown`。能力应按**账号连接 + 平台内容类型 + 操作**记录，而不是平台级一个布尔值。

所有能力都由 [发布任务状态](workflows.md) 统一解释。第三方 MCP 返回“success”时，适配层仍需判断它表示填表、提交还是最终发布。

## 8. 持久化任务与一致性

1. 创建发布意图、冻结快照、记录待执行事件应处于同一数据库事务边界。
2. 若使用外部队列，采用 outbox 或等效机制，避免数据提交成功但队列丢任务。
3. worker 通过租约领取任务；状态更新校验任务版本和持有者，防止旧 worker 回写覆盖新执行结果。
4. 每个逻辑操作具有稳定幂等键；任务尝试另外编号，重试不会创建新的发布意图。
5. 账号会话和对外提交有同账号互斥；锁失效后不能直接假设旧进程没有产生外部效果。
6. 已获得的远端草稿 / 提交 ID 在下一阶段前持久化。
7. 外部接口不提供幂等能力时，系统无法承诺网络故障下的绝对 exactly-once；通过阶段记录、查询和待核验状态处理。
8. 只有确认未产生对应外部写入的失败，才能直接重试提交步骤。

HTTP 请求只负责接收任务并返回任务 ID，长任务状态通过查询或 SSE 提供。实时流断开不影响服务端保存状态。

## 9. 浏览器与执行节点

- 首阶段先验证服务端浏览器扫码登录是否适用于实际账号，再决定具体实现。
- 一个账号使用独立的会话目录或隔离实例，不用在同一浏览器 Profile 内反复切账号。
- 会话目录、Cookie、浏览器截图应作为私有资源；只保留确有诊断价值的截图并设置清理期限。
- 展示给用户的二维码属于一个有过期时间的登录会话，不能无限期重复使用。
- 若第三方服务仅支持单账号 Cookie 文件，可采用账号独立实例，不把它直接当多租户服务。
- 独立节点通过受限令牌领取已授权账号的任务，任务带租约与心跳；可撤销节点。
- 浏览器扩展不是主流程前提。只有后续真实场景需要时才另立需求。

## 10. 文件、数据与凭据

### 文件

- 使用存储对象 ID 引用素材，不把临时下载 URL 当唯一身份。
- 保留原文件，转换图、封面、卡片属于派生资源。
- 平台上传映射按账号隔离，记录有效期和失效原因。
- 导出包包括内容、媒体顺序、来源版本和必要元数据，排除登录态和模型密钥。
- 页面提取器只访问允许的网页资源；用户配置的内部模型或存储地址走独立配置边界。

### 凭据

- 工作台密码采用成熟的密码散列机制，平台凭据采用成熟的加密机制。
- 加密密钥独立注入，备份说明记录如何恢复密钥；仅备份密文不足以恢复连接。
- 普通业务 API 返回连接状态和能力，不返回完整凭据。
- 服务日志关联任务 ID 与账号 ID，屏蔽令牌、Cookie 及包含密钥的查询参数。

## 11. 开放接口设计方向

首版的内部业务 API 与后续稳定公共 API 可以共用业务层，但是否承诺对外兼容由 `EXT-01` 单独管理。

- 资源：accounts、personas、materials、content-projects、variants、tasks、publish-records。
- 长任务创建成功返回任务标识，客户端按任务查询结果。
- 标准错误包含 `code`、`message`、`task_id`（适用时）及可操作说明。
- 列表有分页、筛选和稳定排序；写入使用预期版本处理并发编辑。
- 外部请求使用权限范围令牌；Webhook 记录事件和投递，MCP 调用同一业务服务。

具体路径与请求结构在技术栈确定后形成 OpenAPI 文档，本文件不冻结尚未实现的端点。

## 13. 进入实现前的最小验证

- `POC-01`：编辑、排版、复制到公众号的效果和格式往返。
- `POC-02`：真实公众号的素材、草稿、发布权限矩阵。
- `POC-03`：容器浏览器登录、持久化、身份核对和状态回传。
- `POC-04`：候选模型与图片服务的能力 / 参数兼容。
- `POC-05`：任务重启恢复、重复投递、提交超时的行为。

POC 状态与产物统一记录在 [开发进度](progress.md)，验证定义见 [决策记录](decisions.md)。
