## 1. 状态口径

- **已确认**：用户已明确表达，或后续实施中已记录确定的取舍。

- **待定**：尚缺偏好、证据或实际验证。
- **已替代**：保留旧结论及被哪个决策替代，不删除历史。

产品需求是否实现仍由 [开发进度](progress.md) 管理；“决策已确认”不等于对应功能已完成。

## 3. 关键方案说明

### DEC-02 产品形态

依据：用户认为浏览器扩展不适合作为产品形态，倾向 Docker 部署。

当前方案：浏览器访问自部署工作台；需要浏览器操作的平台由独立执行模块处理。Docker 可运行在本机、NAS 或服务器，具体支持环境待确认。

影响：发布执行器必须有自己的会话管理和结果回传，不能假定用户浏览器的登录态自动可被容器使用。

### DEC-03 技术栈

主要判断因素：维护者熟悉程度、编辑器选型、排版库可嵌入性、队列维护成本和 Docker 支持。

2026-10-16，用户要求开始开发后，实施选择为：React 19 + Vite 8 + TypeScript，Fastify 5，npm workspaces。

原因：首阶段以单人编辑工作台和明确业务 API 为主，Fastify 能保持入口轻量；共享 Zod schema 和领域类型；前端采用客户端路由，不需要为当前工作台引入 SSR。NestJS 保留为前序候选，实际没有采用。

编辑器先使用 Markdown 源文 + 即时预览，避免富文本往返丢失结构；通过渲染与浏览器场景检查。实际公众号后台粘贴仍需账号验证。Python 媒体能力将通过后续独立服务接入。

### DEC-04 内容版本

采用版本与快照的原因：一份母稿可能对应多个账号，各账号内容独立修改；历史发布不能随着当前编辑变化。

首个实现保存 Markdown 正文、大纲、创作要求及结构化附件；每次保存增加修订，历史恢复产生新修订。采用 AI 结果前核对输入版本，发布计划保存不可变快照。

### DEC-05 部署与队列

首个实现采用关系数据库任务表、事务、租约与手动重试，没有引入 Redis。生产 Compose 运行 PostgreSQL、app 和独立 worker；本机因没有 Docker，使用 PGlite 提供同一 SQL 结构的嵌入式数据库，worker 内联。

本地 PGlite 已执行数据持久化和恢复验证；不能据此宣称外部 PostgreSQL / Linux 容器已验收。生产部署需要单独完成 Compose 构建、健康检查和重启验证。

文件存储为不可变本地对象，备份记录密钥指纹。ZIP 备份有 150 MB 素材容量限制，更大实例后续采用流式或数据库 / 文件卷备份。

### DEC-07 发布能力

本次官方资料确认了公众号草稿与正式发布能力不同，实际账号仍需验证。社区发布工具返回成功也可能仅代表提交。

2026-10-17 已实现官方草稿适配器。连接记录独立于账号档案，密钥和临时令牌按账号隔离；上传检查点仅在连接修订相同时复用。草稿提交前持久化请求快照，超时、格式异常或租约过期进入待核对；查询不到不能认定没有写入。真实账号仍需完成 `POC-02`。用户操作说明见 [公众号草稿与核对](wechat-drafts.md)。

2026-10-18 增加正式发布（`freepublish/submit`、`get`、`batchget`、`getarticle`）与已发表文章统计（`datacube/getarticletotaldetail`）。“已提交”与“已发布”分开；没有发布任务 ID 的不确定结果只在成功发布列表中找唯一一致的文章，查不到时保持待核对，由作者确认后才允许重新提交。正式发布不是群发。浏览器通道见 `DEC-12`。

因此：

- 能力值保留未知状态。
- 自动通道按账号和内容类型验证。
- 平台草稿、提交审核、正式发布分别记录。
- 超时且可能已经产生外部写入时进入待核验。
- 无自动通道时交付成品导出与手工记录能力。

### DEC-08 许可证

2026-10-16 首个实现选择 MIT，便于个人、团队和其他开源项目复用；根目录已有完整许可。2026-10-19 用户确认正式开源采用 MIT。

采用第三方实现时检查选定版本的 LICENSE、NOTICE 和资源依赖。GPL / AGPL 并非一律不可用，独立容器也不是自动免责条件。

### DEC-09 范围与分期

当前路线图保持完整能力目录，但以个人图文流程作为首个可用切片。需要后续明确：

- 首版优先的具体内容类型与模板。
- 公众号草稿接入是否具备可验证账号。
- 自动发布优先小红书还是头条。
- 视频是否确有近期需求。
- `PUB-10` 的平台批次与每个平台内容类型：2026-10-19 用户确认 `DEC-14` 的批次；之后新增平台或内容类型另开批次记录。

### DEC-12 浏览器通道与执行节点

2026-10-18 实施。小红书、头条等没有已验证的官方发布接口，因此采用自托管浏览器自动化，而不是浏览器扩展：

- 执行节点（`apps/executor`）是独立进程，可运行在作者自己的电脑或容器中。节点令牌只在注册 / 轮换时显示一次，服务端只存散列；每个节点只领取授权给它的账号与平台的任务。
- 平台登录会话只保存在节点数据目录，按「平台 + 账号」分别用 AES-GCM 加密。服务器不保存平台 Cookie。
- 扫码登录在 Web 中完成：节点上传登录画面（只覆盖一份临时文件，仅管理员可见，不进素材库），作者在画面上点击或输入，指令加密后交给节点。
- 发布前和点击提交前两次核对实际登录账号。点击提交前持久化「publishing」阶段；之后的任何中断都进入待核对，不自动重试。
- 页面选择器随平台改版会失效，所以“登录成功”不等于“通道可用”：只有当前账号已有一条经节点在内容管理页核验（标题、时间、正文一致且唯一）的发布记录，能力才显示为可用；之前显示“待验证”。
- 平台默认选择器写在 `packages/core/src/browser.ts`，可按账号覆盖地址与选择器；地址只接受该平台已知域名。

### DEC-13 视频与媒体处理

2026-10-18 实施。基础镜像保持轻量：转写、语音、图片和向量使用 OpenAI 兼容接口；视频合成与切片由可选的 One-Creator 媒体服务（`apps/media-service`，FFmpeg）完成，Compose 中为 `media` 配置项。媒体服务按请求编号去重，重启后未完成任务标记失败并可从同一任务继续。生成发布包不等于平台上传。

### DEC-14 PUB-10 平台批次

2026-10-18 为实施冻结以下批次，2026-10-19 用户确认：

| 平台 | 内容类型 | 不在本批次 |
| --- | --- | --- |
| 知乎 | 专栏文章 | 回答、想法、视频 |
| 百家号 | 图文文章 | 动态、视频、图集 |
| B 站 | 视频投稿（单 P） | 专栏、动态、多 P、合集 |

三个平台复用 `DEC-12` 的节点协议，各自的登录、身份核对、提交和查询情况在 [开发进度](progress.md#pub-10-batch) 分别记录；任何一个平台的结果都不代表整批完成。

### DEC-15 定时自动执行

2026-10-18 实施。发布日历默认仍只是计划；作者在单条计划上明确选择「到时保存草稿 / 正式发布 / 交给节点发布」。调度器每次从数据库读取到期计划，重启后自然恢复；每个执行版本只派发一次。错过时间超过 10 分钟时默认转为待处理，作者可改为“恢复后仍执行”。同一账号的平台写入通过账号租约串行，不同账号互不影响；待核对的计划只允许查询，不允许重发。

### DEC-10 实现起点

候选方式：

1. 自建领域与工作台，按库或服务复用排版、热点、模型及发布工具。
2. 基于 AiToEarn、Easel 等现有工作台修改。
3. 基于 Postiz 类排期产品扩展国内平台和创作流程。

比较维度：实际部署成本、账号人设模型匹配程度、编辑与版本体验、国内平台能力、依赖边界、许可证、后续升级成本。

首个切片采用方案 1：自建内容与账号领域逻辑，复用 React、Fastify、Zod、PGlite、markdown-it、fflate、Radix 与 Lucide 等通用依赖。公众号排版目前是自有内联样式渲染，不将 doocs/md 或文颜的候选调研记为实际采用。

## 4. 最小技术验证定义

状态和结果链接只维护在 [开发进度](progress.md)。以下定义各实验要回答什么问题。

<a id="poc-01"></a>
### POC-01 编辑与排版

- 问题：候选编辑器和渲染组件能否支持日常文章，并保持可编辑源稿？
- 输入：一篇自有样文，含图片、引用、列表、代码、长段落、链接。
- 动作：编辑、导入导出、套主题、复制到公众号编辑器、卡片分页。
- 产物：候选版本、效果截图 / 导出样本、格式丢失项和选型建议。
- 对应：`DEC-03`、`DEC-04`、`CRE-03`、`FMT-01`、`FMT-02`。

<a id="poc-02"></a>
### POC-02 公众号实际权限

- 问题：实际账号能调用哪些官方操作？
- 输入：账号产品类型、主体 / 认证情况、已配置的开发能力、执行环境。
- 动作：分别验证获取凭据、上传图片和封面、创建 / 读取草稿；正式发布作为独立操作单独验证。
- 产物：脱敏的请求结果、错误码、账号能力表、官方来源日期。
- 对应：`ACC-04`、`PUB-02`、`PUB-04`、`PUB-05`。
- 约束：草稿权限不得从“有 AppID”推导；发布权限不得从“草稿成功”推导。

<a id="poc-03"></a>
### POC-03 容器浏览器与账号隔离

- 问题：Web 展示二维码、会话持久化、用户交互、身份核对是否可实现？
- 输入：小红书 / 头条候选适配器及版本、容器运行环境、测试账号。
- 动作：首次登录、二维码过期、容器重启、两个账号隔离、身份核对、提交结果查询。
- 产物：平台 / 内容类型能力表、会话生命周期说明、失败阶段与支持环境记录。
- 对应：`PUB-06`、`PUB-07`、`PUB-09`。
- 注意：连接返回“已登录”或固定占位昵称，不能替代真实平台账号身份验证。
- 2026-10-18 已实现节点、会话加密、Web 扫码交互与身份核对，并在本地模拟页面中用真实 Chromium 跑通；真实平台页面与容器内浏览器仍待实测。

<a id="poc-04"></a>
### POC-04 模型能力兼容

- 问题：自定义服务的文本、图片、向量等能力是否按预期工作？
- 动作：连通性、流式或普通文本输出、结构化结果、超时、错误返回；图片和向量分别验证。
- 产物：供应商 / 模型 / 能力兼容表、实际支持参数、用量字段、成本信息来源。
- 对应：`SYS-03`、`SYS-06`、`CRE-02`、`FMT-04`、`MAT-06`。

<a id="poc-05"></a>
### POC-05 任务可靠性

- 问题：队列重复投递、进程重启与外部写入不确定时，任务能否保持正确状态？
- 动作：用可控模拟通道制造写入前失败、写入后回执丢失、重复消息、过期租约、并发修改。
- 产物：状态轨迹、去重结果、恢复说明和队列选型建议。
- 对应：`SYS-04`、`PUB-08`、`NFR-02`、`NFR-03`。
