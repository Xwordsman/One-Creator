# 验证与验收计划

> 日期：2026-10-16。本文定义验证场景，不代表这些场景已经执行。
> 执行结果、环境和完成证据记录在 [开发进度](progress.md) 的需求记录中。

## 1. 验收依据

- 单项功能以 [需求文档](requirements.md) 的验收标准为准。
- 本文场景检查多个功能连接起来后是否仍然正确。
- 选择与本次变更相关的验证，不要求每次修改都重新运行所有流程。
- 验证使用自有或明确可使用的测试素材，真实平台结果与模拟通道结果分别记录。
- 自动检查不能证明平台在所有账号和环境下可用；真实实测只覆盖记录的账号类型、版本与日期。

## 2. 建议的基础样本

### 账号与内容

为检查账号隔离，可创建以下虚构档案：

- 公众号 A：技术实践，严谨，保留引用。
- 小红书 B：生活记录，简洁，偏重图片。
- 小红书 C：学习笔记，结构化，少用表情符号。
- 头条 D：知识解读，用于验证第三类平台版本。

档案创建不要求连接真实平台；真实通道验收另用有权限的测试账号。

### 素材

- 一篇自有文章，含标题层级、列表、引用、图片、代码和外部链接。
- 两张不同尺寸图片、一段很长的中文段落、一段含表情和英文的标题。
- 一个正常网页链接、一个失效链接、一份格式不合法的导入文件。
- 一段带具体数字和出处的资料、一段未提供出处的说法。

### 资源基线

初始可使用 500 条素材、50 个内容项目作为列表和检索的测试数据，记录环境、响应时间和资源占用。这是验证样本建议，不是已经证明的容量上限或最低配置。

## 3. v0.1 端到端场景

### VAL-01 部署、访问与恢复

关联：`SYS-01`、`SYS-02`、`SYS-05`、`NFR-01`、`NFR-04`、`NFR-06`。

步骤：在声明支持的环境启动；初始化用户；保存账号、素材和图片；重启；备份并在干净实例恢复。

检查：

- 按实际部署文档可以完成；健康检查能区分依赖未就绪。
- 未登录不能读取私有数据。
- 重启和恢复后内容、引用、图片保持关联。
- 缺少凭据解密密钥时明确报告连接无法恢复，不表现为数据恢复完全成功。
- 不启用视频、向量服务也能正常手工编辑和导出。
- 保存基准资源数据，不把外部模型延迟混同普通页面查询延迟。

### VAL-02 多账号与偏好隔离

关联：`ACC-01`～`ACC-04`、`CRE-01`、`NFR-01`。

步骤：创建不同定位的人设；同一平台建立 B、C 两账号；共享某个人设并添加账号覆盖偏好；分别创建创作任务。

检查：

- 同平台多账号可同时存在，昵称相似不被错误合并。
- 最终使用的偏好及覆盖来源可查看。
- B 的私有样文、凭据和会话不会出现在 C 的任务中。
- 修改共享人设后历史任务仍指向旧版本。
- 停用账号不删除历史发布记录，也不接收新任务。

### VAL-03 分步创作与编辑恢复

关联：`MAT-01`～`MAT-04`、`CRE-01`～`CRE-04`、`SYS-03`、`SYS-04`、`NFR-02`、`NFR-03`。

步骤：导入素材→建立创作要求→生成并修改大纲→生成正文→局部改写→刷新页面→比较并恢复历史稿。

检查：

- 引用可以回到保存的具体资料。
- 模型失败时已有内容不丢失；只重试失败步骤。
- AI 返回前手工修改正文，迟到结果保留为候选而非覆盖最新稿。
- 双标签页编辑存在版本冲突提示。
- 恢复历史生成新修订，原修订仍可查。

### VAL-04 多平台版本与排版

关联：`CRE-05`、`FMT-01`～`FMT-03`、`REV-01`、`NFR-03`、`NFR-05`。

步骤：从同一母稿生成公众号、小红书和头条版本；修改其中一版；更新母稿；排版并导出。

检查：

- 派生版本的账号、内容类型和来源修订明确。
- 改一版不影响其他版本；更新母稿产生过期提示但不自动重写派生稿。
- 图片、引用、长段落在预览与导出中可用；卡片不截断文字。
- 公众号粘贴效果使用实际编辑器检查，记录浏览器与主题版本。
- 平台规则违规有定位，不默默截断标题或正文。
- 键盘可以完成主要编辑操作，窄屏能查看内容和状态。

### VAL-05 日历、导出与人工记录

关联：`PUB-01`、`PUB-03`、`PUB-04`。

步骤：选定平台版本→创建排期→导出包→在任务中手工回填发布链接和时间。

检查：

- 导出清单对应正确账号、版本、图片顺序。
- 导出与重新导出不会自动生成“已发布”状态。
- 人工回填注明来源为用户记录。
- 调整计划时间不修改已有实际发布时间。
- 不可用自动通道显示明确原因，仍可导出成品。

### VAL-06 公众号草稿能力

关联：`ACC-04`、`PUB-02`、`PUB-04`、`FMT-01`；前置 `POC-02`。

步骤：检查实际账号→上传正文图与封面→创建草稿→读取 / 在平台查看草稿。

检查：

- 平台草稿存在且图片可见，记录草稿 ID。
- 草稿成功显示 `draft_saved`，不显示正式发布。
- 无权限、凭据失效、出口限制和媒体错误给出不同原因。
- 同一任务重复请求不新增重复草稿；上传部分成功时能复用结果。
- 成功路径未获得真实验证时保留 `VERIFY` 或明确限制，不能仅凭模拟成功标 `DONE`。

### VAL-07 发布快照与不确定结果

关联：`CRE-04`、`SYS-04`、`PUB-02`、`PUB-04`、`NFR-02`、`NFR-03`。

使用可控模拟适配器构造：重复点击、任务重投、草稿写入后超时、执行中重启、旧 worker 迟到回写。

检查：

- 一个逻辑意图只形成一个有效任务，重试有独立尝试记录。
- 任务创建后继续编辑正文，任务仍使用原快照。
- 写入可能发生但结果未知时进入 `verification_required`。
- 查询已有平台标识后继续处理，而不是再写一次。
- 过期执行者不能把已确认状态覆盖回执行中。

## 4. v0.2 场景

### VAL-08 定时与任务恢复

关联：`PUB-03`、`PUB-05`～`PUB-08`、`SYS-07`。

检查同账号并发、不同账号隔离、本地排期、平台原生排期、服务器错过执行时间、取消与恢复。

预期：同账号串行；原生定时与本地提交不双重执行；错过时间按规则等待处理；已产生平台效果的取消不会误报成功；待处理事件可通知。

### VAL-09 浏览器通道

关联：`ACC-04`、`PUB-06`、`PUB-07`、`PUB-08`；前置 `POC-03`。

检查二维码过期、刷新登录页、登录恢复、两个账号会话隔离、身份不符、人工交互、提交后查不到结果。

预期：会话可定位和过期；身份核对基于实际账号信息；异常可继续处理；没有回执时保留待核验。记录具体平台和内容类型，不把一个通道的成功扩展到全部平台。

### VAL-10 选题、检索与创作增强

关联：`IDEA-02`、`IDEA-03`、`IDEA-05`、`MAT-05`、`MAT-06`、`ACC-05`、`CRE-06`、`FMT-04`、`FMT-05`、`REV-02`、`REV-03`、`SYS-06`。

检查：

- 数据源失效不清空历史结果，订阅可独立关闭。
- 相同素材重复导入有明确处理结果。
- 语义检索结果含片段与出处，向量模型失效可以继续关键词查询。
- 风格提炼结果可修改且保留样文依据。
- 单张配图重试不重复生成已采用图片。
- 审校对自定义术语的误报可忽略，不静默替换文稿。
- 缺失事实来源标记待核查；生成用量区分实际与估算。

### VAL-11 外部 API、Webhook 与 MCP

关联：`EXT-01`～`EXT-03`、`NFR-01`。

检查令牌权限、撤销、分页、任务幂等请求、事件重复投递、签名校验、MCP 异步任务查询。

预期：不同入口不能绕过业务权限；相同请求不创建重复意图；事件可去重；工具输出保留真实任务状态。

## 5. 后续场景

### VAL-12 指标与复盘

关联：`DAT-01`～`DAT-04`、`ACC-06`、`REV-04`、`IDEA-04`。

检查手工数据、CSV、重复快照、缺失值、累计指标、跨平台口径与复盘建议。

预期：累计数不重复求和，未知不是零；分析说明数据范围；建议采用后只影响选定账号，并生成新偏好版本。

### VAL-13 视频模块

关联：`VID-01`～`VID-03`、`NFR-06`。

检查转写时间位置、字幕修改、输出媒体完整性、切片来源区间、外部视频服务中断及部分产物保留。

预期：产物可以进入素材库；视频服务不可用不影响图文编辑与导出；生成视频不自动代表已完成平台投稿。

### VAL-14 协作、工作流与执行扩展

关联：`SYS-08`、`CRE-07`、`PUB-09`、`PUB-10`、`NFR-01`、`NFR-02`。

检查成员权限、退出成员、节点撤销与断线、未授权账号任务、步骤失败恢复以及新增平台批次。

预期：权限由服务端执行；失联节点不能继续回写有效租约之外的结果；工作流可从失败步骤继续；每个新增平台单独验收。

`OPS-*` 进入排期时再补充对应业务场景，不用其他模块的检查代替它们的验收。

## 6. 证据记录方式

最少记录：需求 ID、步骤、实际结果、代码版本、执行环境、验证日期、测试类型和未覆盖范围。

可以使用命令输出摘要、任务记录、截图和导出样本作为证据。截图和日志应隐藏实际密钥、Cookie、个人资料等无关内容。

证据进入 [进度记录模板](progress.md)，正文中的场景列表不维护另一份“通过 / 未通过”状态。
