# 开发路线图

> 日期：2026-10-16。阶段与版本名称是初始建议，不是已承诺的发布日期。
> 每项需求的实际目标阶段、状态和证据以 [开发进度](progress.md) 为准。

## 1. 交付思路

先完成一条日常可以使用的图文创作链路，再补充自动发现、自动执行和数据反馈。每个阶段都应能交付完整的用户结果，而不是只累积界面入口。

| 阶段 | 目标 | 核心产出 |
| --- | --- | --- |
| M0：基线与验证 | 固定概念、范围和最小技术方案 | 本套文档、关键决策、对应 POC 记录 |
| M1：v0.1 个人图文工作台 | 管理不同账号，从素材写出可发布成品 | Docker、账号人设、编辑与版本、三平台适配、排版、导出、日历 |
| M2：v0.2 创作增强与发布自动化 | 减少选题、配图、发布和重复操作 | 热点、检索、风格、AI 配图、审校、已验证通道、调度、开放接口 |
| M3：v0.3 复盘与扩展 | 将内容表现和创作经验连起来 | 指标、复盘、团队、独立节点、更多平台；视频可选 |
| 后续候选 | 按真实使用需求再排期 | 评论辅助、合作与收益台账 |

“功能齐全”通过保留完整需求目录实现；每次发版依据已验收能力公布支持范围。

## 2. M0：文档基线与最小验证

### 当前已有的交付物

初始文档、需求 ID、验收口径、进度台账及外部来源索引。文档建立与产品实现分别计数。

### 进入开发时的工作顺序

1. 明确主要开发技术栈和部署设备，记录到 `DEC-03`、`DEC-05`。
2. 确认首版图文范围与账号类型，记录到 `DEC-09`。
3. 在实现对应模块之前做最小验证：编辑 / 排版 `POC-01`、模型 `POC-04`、任务恢复 `POC-05`。
4. 公众号通道开始前做 `POC-02`，浏览器通道开始前做 `POC-03`；无须用后续通道验证阻塞基础编辑开发。
5. 选定依赖时记录版本和许可；项目许可证 `DEC-08` 已确认为 MIT。

### 阶段出口

- 维护者知道用什么技术搭第一条可用链路。
- 已确认的结论有依据，尚未验证的外部能力仍显示未知。
- v0.1 的范围与验收口径可直接用于拆开发任务。

## 3. M1：v0.1 个人图文工作台

### 开发切片

| 顺序 | 切片 | 主要需求 | 可演示结果 |
| --- | --- | --- | --- |
| 1 | 基础应用和数据保存 | `SYS-01`、`SYS-02`、`SYS-05`、`NFR-01`、`NFR-04` | Docker 启动、登录、保存数据、备份恢复 |
| 2 | 账号与创作上下文 | `ACC-01`～`ACC-04` | 同平台两个账号和不同人设独立管理 |
| 3 | 素材与选题 | `IDEA-01`、`MAT-01`～`MAT-04` | 保存自己的资料，选择引用并创建内容 |
| 4 | AI 创作与版本 | `SYS-03`、`SYS-04`、`CRE-01`～`CRE-04`、`NFR-02`、`NFR-03` | 从要求到正文，局部修改、版本恢复、失败保留产物 |
| 5 | 多平台成品 | `CRE-05`、`FMT-01`～`FMT-03`、`REV-01` | 一份母稿形成公众号、小红书、头条三类成品 |
| 6 | 发布计划与记录 | `PUB-01`、`PUB-03`、`PUB-04` | 日历排期、成品导出、人工发布回填 |
| 7 | 公众号草稿通道 | `PUB-02`，依赖 `POC-02` | 对具备权限的账号推草稿，并保留平台标识 |
| 8 | 可用性收口 | `NFR-05`、`NFR-06`及已有需求 | 用真实创作任务走通，记录资源与响应基线 |

### 阶段出口

- v0.1 范围内的 P0 需求满足验收并有证据。
- 能从自有素材生成三类平台版本，并导出、记录发布结果。
- 两个不同风格账号的内容、偏好和版本没有串用。
- 重启、模型失败和编辑冲突不会无提示地丢失已保存稿件。
- 备份在干净实例恢复成功。
- `PUB-02` 若因实际账号权限无法验证，保留未完成状态；如调整发版范围，记录明确延期及原因，不以人工导出代替其完成。

重点验收：`VAL-01`～`VAL-07`。其中真实平台验证与模拟通道检查分别记录。

## 4. M2：v0.2 创作增强与发布自动化

### 分组实施

| 分组 | 能力 | 主要需求 |
| --- | --- | --- |
| 更好地选题 | 热点、订阅、账号匹配、系列计划 | `IDEA-02`、`IDEA-03`、`IDEA-05` |
| 更好地积累素材 | 网页 / 历史内容导入、语义检索 | `MAT-05`、`MAT-06` |
| 更像自己的表达 | 样文提炼、模板、语言与事实建议 | `ACC-05`、`CRE-06`、`REV-02`、`REV-03` |
| 更完整的视觉产物 | AI 配图、主题模板 | `FMT-04`、`FMT-05` |
| 更少重复发布操作 | 公众号发布、小红书 / 头条执行、任务调度 | `PUB-05`～`PUB-08` |
| 更清楚地了解使用情况 | 用量、通知、手工指标 | `SYS-06`、`SYS-07`、`DAT-01` |
| 更容易接入外部工具 | REST API、Webhook、MCP | `EXT-01`～`EXT-03` |

### 阶段出口

- 新功能融入已有内容项目和版本体系，不形成独立且无法归档的聊天页面。
- 每个自动发布通道有账号、环境、内容类型和日期明确的验证记录。
- 同账号互斥、重复入队、超时待核验、离线排期等情况符合状态约定。
- 平台失败不影响其他账号的内容编辑与导出。
- 外部接口调用复用同一套权限、任务和能力检查。

重点验收：`VAL-08`～`VAL-11`，以及新功能所影响的既有流程。

## 5. M3：v0.3 复盘与扩展

此阶段按真实使用优先级拆成较小发布批次；团队和视频可以独立启用。

| 方向 | 能力 | 主要需求 |
| --- | --- | --- |
| 内容反馈闭环 | 指标同步、看板、复盘、长期偏好 | `DAT-02`～`DAT-04`、`ACC-06` |
| 更有组织的创作 | 对标观察、工作流、版本评估 | `IDEA-04`、`CRE-07`、`REV-04` |
| 协作与执行扩展 | 团队权限、独立执行节点、更多平台批次 | `SYS-08`、`PUB-09`、`PUB-10` |
| 可选视频 | 转写、脚本合成、长视频切片 | `VID-01`～`VID-03` |

### 阶段出口

- 复盘可追溯到具体发布、版本和数据快照。
- 建议采用后形成新的账号偏好版本。
- 每个新增平台按冻结后的批次范围逐项验收。
- 开启协作后具备服务端权限边界。
- 视频服务故障不影响图文主流程，产物进入相同素材与任务体系。

重点验收：`VAL-12`～`VAL-14`及平台新增案例。

## 6. 后续候选

`OPS-01` 评论汇总与回复辅助、`OPS-02` 合作及收益台账保持在需求目录，暂不承诺版本。进入开发前补齐具体操作范围与验收样例。

## 7. 调整路线图的规则

- 新功能先有需求 ID 和验收，再进入阶段。
- 提前或延后某项，修改 `progress.md` 的目标阶段并在 `changelog.md` 记录原因。
- 通道受外部权限阻塞时，保留阻塞原因和已完成部分，不用模糊的“支持平台”覆盖差异。
- 阶段验收不依赖预计天数或代码行数，以可验证的用户结果为准。
- 估算工作量应在技术选型和最小验证之后进行，本基线不填推测工期。
