# 功能需求与验收标准

> 版本：文档基线 0.1；日期：2026-10-16。
> 本文定义目标能力。优先级、目标阶段、实现状态统一维护在 [开发进度](progress.md)。

## 1. 使用方法

- 每行是可追踪需求，ID 分配后保持不变。
- 验收标准描述用户可观察的结果；实现时可以增加案例，不能以较弱的标准直接替换。
- “支持平台”应具体到平台、内容类型、目标账号和操作能力。
- `草稿保存`、`平台提交`、`正式发布`、`用户回填`分别验收。
- 与第三方平台有关的功能，同时验证成功路径、权限不足和结果不确定的处理。
- 后续阶段的大项实施前可以拆分，拆分关系写入 [变更记录](changelog.md)。

## 2. SYS：系统与基础能力

| ID | 功能及边界 | 初始验收标准 |
| --- | --- | --- |
| <a id="sys-01"></a>SYS-01 | Docker 部署与初始化：Web 主体、配置、数据卷、健康检查 | 在声明支持的环境按部署文档完成首次启动；可创建首个用户；重启后数据保留；缺少必要配置时给出具体原因 |
| <a id="sys-02"></a>SYS-02 | 登录与个人工作空间：首版以单人使用为中心 | 登录、退出、会话过期正常；未登录不能读取私有内容；所有业务数据有明确工作空间归属 |
| <a id="sys-03"></a>SYS-03 | 自带模型密钥：文本、图片、向量模型分别配置 | 至少接通一种文本服务，支持自定义兼容接口地址；可测试连接和选择模型；不支持的能力显示原因；密钥不出现在普通接口响应和日志中 |
| <a id="sys-04"></a>SYS-04 | 异步任务中心：生成、渲染、导入、发布统一可查 | 任务有类型、状态、阶段、时间与错误说明；刷新页面可继续查看；可对适用任务取消或重试；重试与原任务有关联 |
| <a id="sys-05"></a>SYS-05 | 数据持久化、备份与恢复 | 按说明备份数据库、素材及必要配置，在新实例恢复；内容、账号关系和图片可用；凭据密钥的恢复要求明确，不输出明文密钥 |
| <a id="sys-06"></a>SYS-06 | AI 用量与费用记录 | 可按模型、任务、账号查询用量；区分供应商报告值和估算值；未知成本显示未知；重试消耗分别记录 |
| <a id="sys-07"></a>SYS-07 | 任务与账号通知 | 任务失败、登录失效、待处理发布可出现在站内通知；支持已读及跳转来源；相同事件不会无限重复提示 |
| <a id="sys-08"></a>SYS-08 | 团队与权限：后续支持多成员工作空间 | 角色至少能区分管理、编辑和只读；账号和素材按授权范围可见；服务端验证权限；退出成员不能继续访问原空间 |

## 3. ACC：账号与创作风格

| ID | 功能及边界 | 初始验收标准 |
| --- | --- | --- |
| <a id="acc-01"></a>ACC-01 | 账号档案：平台、昵称、平台 ID、主页、分类、启停 | 同平台可建立两个不同账号；可按平台和分类筛选；未登录平台也能先建档、写作；停用后不接收新的发布任务，历史记录保留 |
| <a id="acc-02"></a>ACC-02 | 创作身份 / 人设：定位、受众、语气、栏目、偏好、示例 | 可创建、编辑、复制人设并绑定多个账号；没有样文也能使用；编辑后保留版本，历史稿件知道当时用了哪个版本 |
| <a id="acc-03"></a>ACC-03 | 分层偏好与账号上下文 | 可预览任务最终采用的偏好及来源；账号级设置可覆盖共享偏好；切换账号后不串用另一账号的私有示例；平台字段约束独立校验 |
| <a id="acc-04"></a>ACC-04 | 账号连接与授权状态：支持多种连接方式的记录 | 档案与凭据分开保存；每个连接有方式、状态、最近检查时间；凭据和会话按账号隔离；权限不足、登录失效和未配置可以区分 |
| <a id="acc-05"></a>ACC-05 | 从样文提炼风格档案 | 用户选择自己的样文，生成可编辑的语言与结构建议，能查看样文来源；采用后形成新版本；不要求固定二十篇才能使用 |
| <a id="acc-06"></a>ACC-06 | 长期偏好与学习记录 | 记录用户采用、拒绝和复盘形成的建议；能查看来源、修改或删除；只对所属人设 / 账号生效；新建议不会静默覆盖作者已有设置 |

## 6. CRE：AI 创作与内容管理

| <a id="cre-03"></a>CRE-03 | 编辑器与局部 AI 修改 | 支持手工编辑、自动保存、局部改写、扩写、缩写；AI 候选修改可采用或丢弃；迟到结果不覆盖之后的人工修改 |
| <a id="cre-04"></a>CRE-04 | 内容版本、比较与恢复 | 可查看保存版本及来源，比较正文变化；恢复生成新版本而不是删历史；发布记录始终能定位到当时的版本 |
| <a id="cre-05"></a>CRE-05 | 一稿多平台、多账号版本 | 一份母稿可生成公众号、小红书、头条版本；每版绑定一个目标账号并可独立编辑；母稿更新后提示派生版本可能过期，不自动覆写 |
| <a id="cre-06"></a>CRE-06 | 提示词与写作预设 | 可保存、复制、导入导出模板，声明变量和适用场景；文风参数有解释；任务记录实际模板版本和参数 |
| <a id="cre-07"></a>CRE-07 | 可复用多步骤创作工作流 | 可保存一组有顺序的创作步骤并重复执行；每步输入输出可查；失败可从指定步骤继续；结果与执行版本对应 |

## 9. PUB：发布与日历

| ID | 功能及边界 | 初始验收标准 |
| --- | --- | --- |
| <a id="pub-01"></a>PUB-01 | 成品导出、复制与人工发布记录 | 可导出正文、HTML 或卡片、封面及清单；记录目标账号、版本、发布时间与平台链接；人工记录标明来源；再次导出不表示再次发布 |
| <a id="pub-02"></a>PUB-02 | 公众号官方草稿通道 | 有权限账号完成正文图片上传、封面素材上传和新增草稿；保存平台草稿 ID；无权限时给出原因并可导出；重复点击同一操作不新增重复草稿 |
| <a id="pub-03"></a>PUB-03 | 内容日历与排期 | 按账号、平台、状态查看计划；可调整尚未提交任务的时间；展示时区；计划日期、实际提交时间、实际发布时间分别记录 |
| <a id="pub-04"></a>PUB-04 | 平台适配器与能力声明 | 每个平台、账号连接能分别声明导出、草稿、发布、定时、查询能力；未知能力不当作可用；UI 按能力提供入口，保留未支持原因 |
| <a id="pub-05"></a>PUB-05 | 公众号官方发布与查询 | 对有权限账号提交指定草稿并查询结果；“已提交”与“已发布”区分；记录平台返回 ID 和状态；不把发布操作等同于群发消息 |
| <a id="pub-06"></a>PUB-06 | 小红书浏览器发布通道 | 从 Web 完成二维码登录流程；图文任务绑定独立会话；发送前核对账号；能处理过期、待交互、提交后结果不确定；按实测范围展示支持情况 |
| <a id="pub-07"></a>PUB-07 | 头条文章浏览器发布通道 | 用指定账号完成文章与媒体填写及提交；保留平台回执或可核验记录；失败可定位阶段；头条文章能力不混同微头条或视频 |
| <a id="pub-08"></a>PUB-08 | 定时调度、多账号队列与去重 | 同一账号串行执行；不同账号隔离；相同任务重投不重复提交；实例重启能恢复计划；结果不确定先核验；过期排期与取消规则符合状态约定 |
| <a id="pub-09"></a>PUB-09 | 独立执行节点 | 节点可注册、撤销、报告在线状态和支持能力；任务绑定节点及账号；节点掉线有可恢复记录；凭据只交给有权执行的节点 |
| <a id="pub-10"></a>PUB-10 | 更多平台发布批次：候选知乎、百家号、B 站等 | 开发前冻结本批次平台和内容类型；每个平台分别记录登录、校验、提交、查询及未支持项；不能用一个平台的成功表示整批完成 |

## 14. NFR：质量要求

| ID | 要求 | 验收方式 |
| --- | --- | --- |
| <a id="nfr-01"></a>NFR-01 | 数据边界与凭据保护 | 检查未登录访问、越权读取、跨工作空间引用；检查日志与导出中的密钥脱敏；凭据加密所需密钥不和密文混作普通业务字段 |
| <a id="nfr-02"></a>NFR-02 | 异步执行可恢复 | 任务执行中重启进程后仍可查到状态；有阶段、尝试次数和恢复入口；已触发外部写入的任务先核实结果再重试 |
| <a id="nfr-03"></a>NFR-03 | 编辑与版本一致性 | 刷新恢复已保存稿件；双标签页编辑能检测冲突；迟到 AI 输出不覆盖新版本；发布快照不随当前编辑变化 |
| <a id="nfr-04"></a>NFR-04 | 可升级与可恢复部署 | 记录迁移步骤和支持版本；升级前可备份；在干净环境演练恢复；不能把旧镜像直接连接新结构数据库当作保证可回滚 |
| <a id="nfr-05"></a>NFR-05 | 可用的中文工作台体验 | 核心表单有标签并能键盘操作；切换账号和执行动作时目标清楚；空态、加载、保存失败可区分；窄屏能查看稿件与任务状态 |
| <a id="nfr-06"></a>NFR-06 | 渐进资源消耗与故障降级 | 文本基础部署不要求视频/GPU/向量服务；外部模型或数据源不可用时仍能手工编辑和导出；长任务异步执行；记录基准环境、数据量、响应时间和内存结果 |

## 15. 首批平台的需求边界

| 平台 / 内容类型 | 成品生成与导出 | 自动通道目标 | 不能从中推导出的能力 |
| --- | --- | --- | --- |
| 公众号图文文章 | 平台版本、微信排版、封面、HTML | 草稿接口，后续按权限接发布查询 | 所有个人号均可发草稿；发布等于群发 |
| 小红书图文笔记 | 标题、正文、话题、卡片、封面 | 后续浏览器执行器 | 所有账号均能无人值守；具备官方发布 API |
| 头条文章 | 标题、正文、图片、导出包 | 后续浏览器执行器 | 自动包含微头条、视频、全部互动能力 |

平台限制以带版本的规则配置维护，不能把社区项目中的篇幅、页数和每日上限直接当作永久平台规则。

## 16. 关键依赖

- 账号上下文链：`SYS-02` → `ACC-01` / `ACC-02` → `ACC-03` → `CRE-01`。
- 内容资产链：`MAT-01` / `MAT-02` → `MAT-04` → `CRE-02` / `CRE-04` → `CRE-05`。
- 发布基础链：`ACC-04` + `CRE-04` + `REV-01` + `PUB-04` → `PUB-02` / `PUB-05` / `PUB-06` / `PUB-07`。
- 调度链：`SYS-04` + 发布基础 → `PUB-08`，执行节点扩展为 `PUB-09`。
- 反馈链：发布记录 → `DAT-01` / `DAT-02` → `DAT-03` / `DAT-04` → `ACC-06`。
- 视频链：素材、任务、存储和模型配置稳定后，再启用 `VID-*`。

这些是业务依赖，不强制映射为独立微服务。
